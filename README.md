# Requirements Analysis for Service Platforms

Проект посвящён выявлению, анализу и согласованию требований к информационным системам на примере двух предметных областей: сервиса доставки заказов и системы онлайн-записи в барбершоп.

Основной фокус проекта — переход от исходной бизнес-задачи и проблем пользователей к структурированным бизнес-требованиям, ролям системы, потребностям пользователей и границам будущего решения.

## Предметные области

### Сервис доставки

Система предназначена для автоматизации работы службы доставки.

Основные участники:
- поставщики заказов;
- оператор;
- курьеры;
- диспетчер;
- администратор;
- бухгалтерия;
- клиент.

Система должна позволять централизованно принимать заказы, распределять их между курьерами, отслеживать выполнение доставки, обрабатывать проблемные ситуации и передавать данные во внешнюю бухгалтерскую систему.

### Онлайн-запись в барбершоп

Вторая предметная область — сервис онлайн-записи клиентов.

Основные задачи системы:
- выбор услуги, мастера и времени;
- управление расписанием;
- автоматические уведомления;
- фиксация оказанных услуг;
- оплата;
- получение отзывов клиентов;
- взаимодействие с бухгалтерией.

Эта предметная область использовалась как параллельный кейс при анализе требований и сравнении подходов к построению систем.

## Что исследовалось

В проекте применялись несколько техник выявления требований:

- ролевая игра;
- brainstorming;
- рабочий семинар;
- анализ заинтересованных сторон;
- анализ проблем AS IS;
- формирование потребностей и действий TO BE;
- определение границ системы;
- подготовка Vision / BRD.

Особое внимание уделялось тому, чтобы отделить проблемы, которые может решить информационная система, от организационных, финансовых и правовых проблем.

## Структура проекта

### `ex00_QDP_rolegame.pdf`

Отчёт о ролевой игре по системе доставки.

Участники последовательно рассматривали систему с точки зрения разных ролей и отвечали на вопросы:

- для кого создаётся система;
- какие потребности есть у каждой роли;
- с какими проблемами она сталкивается;
- как устроен текущий процесс;
- какие действия пользователь хотел бы выполнять в будущей системе;
- какие данные и интеграции необходимы.

В рамках ролевого анализа рассматривались курьер, поставщик, администратор, оператор, диспетчер, бухгалтер, клиент и представитель команды разработки.

### `ex01_QDP_brainstorming.pdf`

Протокол мозгового штурма.

В документе собраны и структурированы:

- основные проблемы текущего процесса доставки;
- предложения для бизнес-требований;
- проблемы пользователей в состоянии AS IS;
- идеи по возможностям будущей системы;
- потенциальные интеграции;
- вопросы, не имеющие однозначного решения.

Отдельно рассматривались противоречия между гибкостью работы курьеров, скоростью доставки, справедливой оплатой и уровнем автоматизации.

### `ex02_QDP_seminar.pdf`

Результаты командного семинара.

На этом этапе идеи, полученные ранее, уточнялись и согласовывались.

В документе зафиксированы:

- бизнес-требования;
- цели системы;
- роли;
- проблемы пользователей;
- потребности TO BE;
- предполагаемые действия пользователей;
- решения спорных вопросов;
- функциональные границы системы.

### `ex03_QDP_vision.pdf`

Итоговый Vision / BRD.

Документ объединяет результаты предыдущих этапов и описывает концепцию будущей системы.

Содержит:

- описание проблем;
- бизнес-цели;
- заинтересованные стороны;
- роли пользователей;
- основные функции;
- границы системы;
- внешние взаимодействия;
- потенциальные интеграции;
- критерии и ограничения решения.
